# Audit of Stage 1, 2026-11-18

Stage 1, the headless core, examined whole before 0.1, as the method's stage audit asks: every
dimension, independent reviewers, each finding verified, the owner deciding what changes direction.

## Scope

- **Code and documents** at `9fe08b7` (M1.12 done, Rust 1.100.0): the four crates, `scripts/`,
  `flake.nix`, the workflows, `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, `docs/` and the ADRs.
- **Dimensions**: all of the method's. Correctness, edge cases, security and data safety in three
  parts (the compositor's core, XWayland and its bridge, the MCP server and the program);
  architecture, evolvability, stability and recovery, and Stage 1's exit; documentation,
  readability and the chains of ADRs; dependencies; the tests (mutation testing, skipped tests,
  flakiness); the known debt, triaged. Accessibility: Yuna has no interface of its own yet; reduced
  motion was checked. Performance and rest: measured again on the release candidate, after the
  tag (*Release*, below).
- **Evidence**: eight independent reviewers, each in a worktree of its own, given the code and the
  bar, never the expected conclusions; the judgement calls on the strongest model. Every finding
  below was shown by a test that failed, a command, a measurement, or the exact line with its
  reasoning; what could not be shown is marked a doubt. Each fix was then written by an author
  under a brief, read by a checker with fresh eyes, and corrected once.

## Verdict

- The core stands: a pure layout model under property tests, a clock that owns every deadline,
  415 headless stories that speak the real protocols, real applications in CI, rest checked on the
  program, no `unwrap` or `panic!` in production code. No data loss was found.
- One client or one X11 program could still stop, stall or exhaust Yuna in ways the bounds of
  ADR-0028 and ADR-0070 did not cover: 14 findings of the first severity. All but those the owner
  kept as debt are fixed and tested.
- Stage 1's exit was not met as written (Aerith has no window); the owner amended it, Opium in
  Aerith's place, and the exit is now met but for the weekly Opium job's first run on GitHub.
- The documents had outgrown the code: `ARCHITECTURE.md` grew 56 % after the last audit asked to
  shrink it; 24 topics needed several ADRs to read. Both are done.

missed; (4) readability and documentation. Each with its fix's commit or its debt.

## Tests

- **Mutation testing** (cargo-mutants 27.1): `yuna-layout` 83 %, `yuna-motion` 79 %, `keymap.rs`
  85 %, `drag_session.rs` 92 % of viable mutants caught; `frames.rs` and `xdnd.rs`, covered by

- **Flakiness**: the headless suite passed three times under load before the fixes; three stories
  that read the machine's speed were found and fixed; the suite runs twice under load before each
  push.

## The newcomer test

An agent new to Yuna, given the repository alone, made a small change: MCP's `pointer` telling
which window a press reached. It found a story that failed one run in two, on the manual clock
(fixed), and that the documents did not say how to run one story, how to format, where the MCP
stories' helpers are, that a tool's results are a contract through its description, nor which ADR
a changelog fragment names (all written since). Its change was not kept: `pointer`'s result names
the window under the pointer already.

## Release

The owner chose on 2026-11-19 to tag 0.1 once the release's commit passed its checks and CI, before
the audit's last two steps: the budgets measured again on the release candidate, and the closing
review by a fresh reviewer. Both follow the tag, the budgets below; what they find goes to a 0.1.1, or to the debt,
and is recorded here. The release's checklist: the changelog gathered under [0.1.0]; the version
0.1.0; the Nix package built in CI; no earlier release to update from; Linux alone, on the owner's
NixOS and CI's Ubuntu. Not done: signed packages and kept debug symbols, which no package
publishes yet.

## Budgets, measured after the tag

On 2026-11-19, on the release candidate ([measurements](../measurements.md)): the layout's "float,
then tile" meets its 25 µs (24.13 µs at the 99th percentile, the profile naming the hashing of
`WindowId`s as its largest cost); a frame's cost and memory in a game stay below Umbriel's; Yuna
rests; ten `yuna mcp` together grow nothing. Three of `yuna mcp`'s start budgets were missed on a
quiet machine, its first frame on the GPU at 1080p, its `seat create` and its memory on llvmpipe
at 4K, the cause not isolated: debt for 0.1.1. Motion was not judged, the machine disturbed. Yuna's
memory kept after an Xwayland on llvmpipe is not glibc's free lists.
